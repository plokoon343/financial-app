1. **Inventory first (no changes):** list every current DNS record for automonie.com and subdomains (A, AAAA, CNAME, MX, TXT incl. SPF `include:spf.brevo.com include:zoho.com`, DKIM for Brevo and Zoho, DMARC, Google/Vercel verification, `www` and apex to Vercel, `api` to Render, `in` MX to Postmark, any CAA). 2. **Worker:** `infra/email-worker/` (Wrangler project): an Email Worker bound to catch-all on `in.automonie.com` (or the address pattern `<token>@in.automonie.com`) that parses the raw MIME with `postal-mime`, drops anything over a size cap, and POSTs JSON to `https://api.automonie.com/api/inbound-email/cloudflare` with a shared secret header. Reject (setReject) mail with no valid token in the address so bad senders get a bounce, not a silent drop. Keep it small and commented.
3. **Backend:** new route `/api/inbound-email/cloudflare` that maps the Worker's JSON to the same internal shape the Postmark webhook uses and calls the same ingest path (token lookup, known-bank sender check, Gmail verification auto-detect, parse, dedupe). Secret `INBOUND_CF_SECRET` (constant-time compare). Keep the Postmark route working until the switch-over is confirmed, then leave it as a fallback. Tests for the mapping and the auth.

Zoho (hello@ mailboxes) MX on the apex stays as it is: Email Routing is only enabled for the `in` subdomain.
5. **Risk notes for the owner:** the nameserver switch is the only moment something can break (site, app API, email). Do it after the inventory is checked, at a quiet hour; DNS changes can take up to a few hours to settle. Nothing about user accounts or data changes.
