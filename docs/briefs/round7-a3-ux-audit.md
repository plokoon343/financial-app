# Round 7, A3: UX and UI audit (26 Oct 2026, Sonnet)

## Method

Walked the mobile app through the Expo web preview (`mobile-web` launch config) against a local API (`backend`, pointed at a throwaway `automonie_audit_test` MongoDB database via a new `api-test` launch config) seeded with `scripts/seed-play-review.js` (42 transactions, 2 accounts, budgets, a goal, bills, 3 review alerts, 6 recurring-charge candidates). Logged in as that seeded account (`audit-tester@automonie.com`) in Light and Dark at 360×800 and spot-checked 412×915. Also walked the web app (`frontend`, same local API) at desktop width and at 375×812 mobile width.

**Setup note:** the dev CORS allow-list (`backend/server.js`) didn't include `http://localhost:8081` (the `mobile-web` preview's origin), so sign-in failed with a CORS error until I added `ALLOWED_ORIGINS=http://localhost:8081` to the new `api-test` launch config entry in `.claude/launch.json`. That's a launch-config-only change (dev-only; `ALLOWED_ORIGINS`/this whole origin branch is compiled out in production) — kept so A1/A2's sessions, and any future one, can reuse the same `api-test` config without re-discovering this.

**Coverage, honestly:** this is a thorough pass over the primary flows (onboarding → login → Home → Money → Plan (Grow) → Profile → Action Center → Add Transaction → Insights → Email forwarding), both themes, two widths, plus a web app pass — not literally every screen in the app (Goals detail, Subscriptions, Bills, Settings sub-screens, Connect Bank, and the Ask assistant weren't opened this round). What's here is real and verified, not a guess; what isn't here should get a follow-up pass before Play submission if time allows.

## Findings

| # | Screen | Issue | Severity | Fix |
|---|--------|-------|----------|-----|
| 1 | **Every screen that shows a ₦ amount** (mobile app) | The bundled Poppins font (`@expo-google-fonts/poppins`, all weights) has **no glyph for the NAIRA SIGN (U+20A6)** — confirmed with `fontTools` against the actual `.ttf`. In the Expo web preview this makes the browser substitute a fallback font for the glyph run, which renders as a line straight through the entire amount (not just the ₦ symbol) — see screenshots. Reproduced on Home, Money, Plan, Profile, Action Center: everywhere money is shown. Web app is unaffected because its CSS declares a font **stack** (`'Poppins', -apple-system, ..., sans-serif`, in `frontend/src/theme.css`), so the browser swaps just the missing glyph cleanly; React Native's `fontFamily` takes one name only, so mobile has no such fallback. | **Critical** | Root cause is confirmed; the on-device visual result on real iOS/Android is not (native font-fallback engines may hide this where Chromium's didn't) — verify in the S9 phone test as the first thing checked. Either way the font gap is real and worth closing before Play submission: render the ₦ sign as its own `Text` in a font confirmed to carry it (e.g. system font) instead of inline with the Poppins amount, or switch to a Poppins build/alternate weight that does include U+20A6. Not fixed here — this is a "big fix" for the F session, not a safe inline edit. |
| 2 | Money screen, transaction list (mobile) | Amounts under ₦1,000 always showed 2 decimals (`-₦500.00`) while amounts ₦1,000–₦9,999 showed none (`-₦3,600`) in the *same list*, because `formatNaira` switched precision at a different threshold than it switched to compact notation. Reads as inconsistent, not as "more precise." | Medium | **Fixed directly**: [`finpilot-mobile/src/lib/format.ts`](../../../finpilot-mobile/src/lib/format.ts) now shows kobo only when the amount actually has them (`Math.round(abs*100) % 100 !== 0`), regardless of magnitude. Verified before/after on the Money screen (screenshots 05/06); `npx tsc --noEmit` clean. |
| 3 | Console, mobile web preview | `Invalid DOM property 'transform-origin'. Did you mean 'transformOrigin'?` logged repeatedly. A style object somewhere is built with a raw CSS property name instead of RN's camelCase, which React Native Web has to warn about and reinterpret. Did not find the exact source file in the time available (not a literal string match — likely built dynamically, possibly in an animation/chart helper). | Low | Grep the mobile source for anywhere a style object is spread from a non-literal source (chart libs, reanimated interpolations) and check for a `'transform-origin'` key; rename to `transformOrigin`. Console-only as observed — no visual defect seen — so low priority, but cheap to track down. |
| 4 | Login (mobile) | The "Sign In" button and the "Don't have an account?" row render as unlabelled `generic` nodes in the accessibility tree (no `accessibilityRole="button"`/accessible name), unlike the password field's own "Show password" button which is correctly labelled. A screen-reader user gets an unnamed element instead of "Sign In, button." | Medium | Add `accessibilityRole="button"` + `accessibilityLabel="Sign In"` to the submit control (same pattern already used elsewhere in this file, e.g. the eye-icon toggle in `index.tsx`). Not fixed here — didn't want to touch auth-flow code without a device check in hand. |
| 5 | Login → "Create one" (mobile) | The link goes to `/onboarding` (the marketing carousel) rather than straight to `/register`, adding a Skip tap before someone who already knows they want to sign up can start. | Low | Point the link at `/register` directly; `/onboarding` is for first-touch installs, not for someone already on the login screen. |
| 6 | Home **and** Money tabs, first visit (mobile) | Two separate full-screen interstitials fire back to back within the first session view: Home shows "Your weekly recap is ready," and switching straight to Money shows a *second*, different one, "Your daily recap is ready." Both are dismissible, but stacking two promotional modals in under a minute reads as nagging on a first run. | Low–Medium | Consider a per-session cap (one recap nudge shown per app open, whichever is due) rather than one per screen that has one pending. |
| 7 | Profile header (mobile) | `audit-tester@automonie.com · Pl...` — the plan label after the email gets clipped mid-word by the row's fixed width, on a 360px screen. | Low | Either drop the plan label here (it's shown again as the avatar ring / elsewhere) or wrap to a second line instead of truncating a 2-letter-visible fragment. |
| 8 | Money app settings icon, top-right (web) | The gear icon in the login screen's top-right corner has no accessible name (`button` with no label in the a11y tree). | Low | Add an `aria-label` ("Settings" or similar). |

## What I checked and found *not* to be a bug

- **Web app sidebar at narrow widths**: first pass looked broken (sidebar pinned open, content clipped) — but that was from resizing an already-loaded desktop session. A **fresh load** at 375×812 renders the correct mobile layout (hamburger + bottom tab bar), and rotating the viewport mid-session (375→812 width) correctly re-flows to the desktop sidebar. Real responsive behaviour is fine; flagging only so the next person doesn't re-chase this.
- **"9 to review" (Home) vs "Alerts to check 3" (Action Center)**: reconciles correctly — 3 alerts + 6 recurring-charge candidates = 9. Two different labels for a sum vs. a breakdown, not a miscount.
- **Dark mode contrast, tap targets, the Add-Transaction sheet, the Email-forwarding screen's step-by-step guide**: all read cleanly at both widths; no issues found.
